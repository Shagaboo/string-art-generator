## Общее описание

String Art (ниткография) — это техника создания изображений путем натягивания нитей между гвоздями, расположенными по контуру. Алгоритм преобразует черно-белое изображение в последовательность линий, которые при натягивании создают визуальное представление исходного изображения.

### Основная идея
- **Темные области** изображения = **больше нитей** (высокая плотность линий)
- **Светлые области** изображения = **меньше нитей** (низкая плотность линий)
- Алгоритм итеративно выбирает линии, которые "осветляют" темные области, приближая текущее изображение к оригиналу

## Математическая модель

### Переменные
- `original[i]` — яркость пикселя `i` в оригинальном изображении (0-255)
- `current[i]` — текущая яркость пикселя `i` после нарисованных линий (0-255)
- `error[i] = original[i] - current[i]` — ошибка восстановления пикселя `i`
- `lineWeight` — вес линии (насколько ярче становится пиксель при прохождении нити)

### Модель накопления света
При рисовании линии от гвоздя `A` к гвоздю `B`:
```
для каждого пикселя p вдоль линии AB:
    current[p] = min(255, current[p] + lineWeight)
```

### Критерий выбора линии
Алгоритм выбирает линию, которая **максимально уменьшает ошибку**:
```
improvement = Σ (error_before[p] - error_after[p]) для всех p вдоль линии
```

Где:
- `error_before[p] = max(0, original[p] - current[p])`
- `error_after[p] = max(0, original[p] - (current[p] + lineWeight))`

## Пошаговый алгоритм

### Шаг 1: Предобработка изображения

1. **Конвертация в grayscale**
   ```
   lightness = 0.2126 * R + 0.7152 * G + 0.0722 * B
   ```
   Используются стандартные веса для восприятия яркости человеческим глазом.

2. **Инверсия (опционально)**
   ```
   if invert: lightness = 255 - lightness
   ```

3. **Коррекция яркости**
   ```
   brightnessFactor = 1.0 + brightness / 100.0
   lightness = lightness * brightnessFactor
   ```

4. **Коррекция контраста**
   ```
   contrastFactor = 1.0 + contrast / 100.0
   lightness = (lightness - 128) * contrastFactor + 128
   ```

5. **Гамма-коррекция**
   ```
   normalized = lightness / 255.0
   corrected = normalized^(1/gamma)
   lightness = corrected * 255.0
   ```
   Гамма < 1.0 усиливает темные области (делает их темнее), что улучшает контраст.

### Шаг 2: Генерация гвоздей

Гвозди размещаются по контуру выбранной формы:

#### Формы размещения:
- **Круг**: равномерное распределение по окружности
- **Прямоугольник**: равномерное распределение по периметру
- **Случайное**: случайные точки с минимальным расстоянием между гвоздями
- **Полу-сетка**: комбинация сетки и случайных точек

#### Минимальное расстояние
Для предотвращения скопления гвоздей:
```
minDistance = max(10, nailCount / 15)
```
Проверяется расстояние между каждым новым гвоздем и уже размещенными.

### Шаг 3: Итеративная генерация линий

Алгоритм работает итеративно, на каждой итерации генерируя одну линию:

```
1. Начинаем с гвоздя currentNail (изначально 0)
2. Для каждого кандидата (другого гвоздя):
   a. Вычисляем среднюю яркость пикселей вдоль линии
   b. Вычисляем улучшение ошибки (error improvement)
3. Выбираем гвоздь с максимальным улучшением
4. Рисуем линию: обновляем current[p] для всех пикселей вдоль линии
5. Переходим к выбранному гвоздю
6. Повторяем шаги 2-5 N раз (N = количество линий)
```

### Шаг 4: Вычисление линии (алгоритм Брезенхема)

Для эффективного вычисления пикселей вдоль линии используется алгоритм Брезенхема:

```go
func BresenhamBrightness(x0, y0, x1, y1, grayscale, width, height):
    sum = 0
    count = 0
    для каждого пикселя (x, y) вдоль линии:
        idx = y * width + x
        sum += grayscale[idx]
        count++
    return sum, count
```

### Шаг 5: Обновление изображения

После выбора линии обновляем яркость пикселей:

```go
func BresenhamUpdate(x0, y0, x1, y1, grayscale, width, height, lineWeight):
    для каждого пикселя (x, y) вдоль линии:
        idx = y * width + x
        grayscale[idx] = min(255, grayscale[idx] + lineWeight)
```

## Обработка изображения

### Конвейер обработки

```
RGBA изображение
    ↓
Grayscale (0.2126*R + 0.7152*G + 0.0722*B)
    ↓
Инверсия (опционально)
    ↓
Таблица яркости (brightnessTable)
    ↓
Таблица контраста (contrastTable)
    ↓
Таблица гамма-коррекции (gammaTable)
    ↓
Финальный grayscale массив
```

### Таблицы предвычисления

Для оптимизации все преобразования выполняются через предвычисленные таблицы:

```go
brightnessTable[i] = limitPixel(i * (1.0 + brightness/100.0))
contrastTable[i] = limitPixel((i - 128) * (1.0 + contrast/100.0) + 128)
gammaTable[i] = limitPixel((i/255.0)^(1/gamma) * 255.0)
```

Это позволяет обрабатывать каждый пиксель за O(1) вместо вычисления формул.

## Генерация гвоздей

### Алгоритм размещения

#### Круг
```go
for i := 0; i < nailCount; i++ {
    angle = 2 * π * i / nailCount
    x = centerX + radius * cos(angle)
    y = centerY + radius * sin(angle)
}
```

#### Прямоугольник
```go
perimeter = 2 * (width + height)
step = perimeter / nailCount
for i := 0; i < nailCount; i++ {
    pos = step * i
    if pos < width:
        x = pos, y = 0
    else if pos < width + height:
        x = width, y = pos - width
    else if pos < 2*width + height:
        x = width - (pos - width - height), y = height
    else:
        x = 0, y = height - (pos - 2*width - height)
}
```

#### Проверка минимального расстояния
```go
minDistance = max(10, nailCount / 15)
for каждого нового гвоздя:
    for каждого существующего гвоздя:
        if distance(newNail, existingNail) < minDistance:
            отклонить новый гвоздь, попробовать снова
```

## Выбор линий

### Алгоритм выбора (Error Improvement)

На каждой итерации алгоритм выбирает линию, которая максимально уменьшает ошибку восстановления:

```go
func GenerateNextLine(currentNail, nails, grayscale, lineWeight):
    maxImprovement = 0
    bestNail = -1
    
    for каждого кандидата nail (nail != currentNail):
        improvement = 0
        count = 0
        
        для каждого пикселя p вдоль линии (currentNail -> nail):
            errorBefore = max(0, original[p] - current[p])
            newCurrent = min(255, current[p] + lineWeight)
            errorAfter = max(0, original[p] - newCurrent)
            improvement += (errorBefore - errorAfter)
            count++
        
        if improvement > maxImprovement:
            maxImprovement = improvement
            bestNail = nail
    
    // Рисуем линию
    для каждого пикселя p вдоль линии (currentNail -> bestNail):
        current[p] = min(255, current[p] + lineWeight)
    
    return bestNail
```

### Параллелизация

Для ускорения проверка кандидатов выполняется параллельно:

```go
workers = min(max(4, CPU_count), 32)
chunkSize = nailCount / workers

for каждого воркера w:
    параллельно проверяем nails[w*chunkSize : (w+1)*chunkSize]
    находим лучший кандидат в своем чанке

находим глобально лучший кандидат среди всех воркеров
```

## Оптимизации

### 1. Inline Bresenham
Вместо предвычисления всех линий (что требует огромной памяти), линии вычисляются на лету с помощью inline-функций Брезенхема. Это экономит память и позволяет обрабатывать большие изображения.

### 2. Таблицы предвычисления
Все преобразования изображения выполняются через предвычисленные таблицы размером 256 элементов, что дает O(1) доступ вместо вычисления формул.

### 3. Параллельная обработка
Проверка кандидатов распараллеливается на несколько воркеров (4-32 в зависимости от CPU).

### 4. Batch SSE
Прогресс отправляется клиенту батчами (200-1000 линий), а не после каждой линии, что снижает overhead сети.

### 5. Минимальное расстояние между гвоздями
Предотвращает создание очень коротких линий, которые не несут полезной информации, но увеличивают шум.

## Сложность алгоритма

- **Время**: O(L × N × P)
  - L = количество линий
  - N = количество гвоздей
  - P = среднее количество пикселей в линии
  
- **Память**: O(W × H + N)
  - W × H = размер изображения
  - N = количество гвоздей

- **Параллелизация**: O(L × (N/W) × P)
  - W = количество воркеров

---

## Параметры алгоритма

### Входные параметры
- `nailCount` (700-2000): количество гвоздей
- `lineCount` (10000-50000): количество линий
- `lineOpacity` (5-15%): вес линии (насколько ярче становится пиксель)
- `brightness` (-50 до +50): коррекция яркости
- `contrast` (0 до 100): коррекция контраста
- `gamma` (0.5-1.5): гамма-коррекция (по умолчанию 0.7 для усиления теней)
- `shape`: форма размещения гвоздей (круг, прямоугольник, случайное, полу-сетка)

### Рекомендуемые значения
- **Портреты**: 700 гвоздей, 20000-30000 линий, opacity 6-10%
- **Пейзажи**: 1000-1500 гвоздей, 30000-40000 линий, opacity 8-12%
- **Детальные изображения**: 1500-2000 гвоздей, 40000-50000 линий, opacity 10-15%

## Результат

Алгоритм генерирует последовательность линий `LineSegment[]`, где каждая линия определяется парой индексов гвоздей `(from, to)`. При визуализации эти линии создают изображение, приближенное к оригиналу.

### Экспорт для ЧПУ
Результат может быть экспортирован в форматы:
- **G-code**: для прямого управления ЧПУ станком
- **JSON**: для программной обработки
- **CSV**: для табличных редакторов
