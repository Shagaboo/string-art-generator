# String Art Generator - Презентация проекта

## 🎯 О проекте

**String Art Generator** — веб-приложение для автоматической генерации string art (ниткографии) из фотографий. Проект преобразует черно-белые изображения в последовательность линий, которые можно реализовать физически, натягивая нити между гвоздями.

---

## 💡 Основная идея

String art — это техника создания изображений путем натягивания нитей между гвоздями. Алгоритм автоматически определяет:
- **Где разместить гвозди** (по контуру формы)
- **В каком порядке натягивать нити** (последовательность линий)
- **Какие области затемнить** (больше нитей = темнее)

**Результат:** Физическое произведение искусства, созданное по алгоритму.

---

## 🔬 Алгоритм

### Математическая модель

1. **Предобработка изображения**
   - Конвертация в grayscale
   - Коррекция яркости, контраста, гаммы
   - Усиление темных областей

2. **Генерация гвоздей**
   - Размещение по контуру (круг, прямоугольник, сетка)
   - Проверка минимального расстояния (избегание скоплений)

3. **Итеративная генерация линий**
   - На каждой итерации выбирается линия, которая **максимально уменьшает ошибку** восстановления
   - Алгоритм работает с остаточной ошибкой: `error = original - current`
   - Выбирается линия с максимальным улучшением: `improvement = error_before - error_after`

4. **Обновление изображения**
   - После выбора линии обновляется яркость пикселей: `current[p] += lineWeight`

### Ключевая формула

```
Для каждой линии-кандидата:
    improvement = Σ (error_before[p] - error_after[p])
    
Где:
    error_before[p] = max(0, original[p] - current[p])
    error_after[p] = max(0, original[p] - (current[p] + lineWeight))
```

**Выбираем линию с максимальным improvement.**

## ⚡ Оптимизации

### 1. Inline Bresenham
Вместо предвычисления всех линий (требует ~400MB памяти), линии вычисляются на лету. **Экономия: 200x меньше памяти.**

### 2. Таблицы предвычисления
Все преобразования изображения через предвычисленные таблицы (256 элементов). **Ускорение: 3-5x.**

### 3. Параллелизация
Проверка кандидатов распараллеливается на 4-32 воркера. **Ускорение: 4-8x.**

### 4. Batch SSE
Отправка прогресса батчами (200-1000 линий). **Снижение overhead: 90%+.**

### Результат
- **Скорость:** 800-1300 линий/сек (vs 300-500 в JavaScript)
- **Память:** ~50MB (vs ~500MB с кэшем)
- **Ускорение:** **2.5-4x** по сравнению с JavaScript версией

## 🔧 Технические детали

### Алгоритм Брезенхема
Используется для эффективного вычисления пикселей вдоль линии:
- Только целые числа (нет float операций)
- In-place вычисление (не выделяет память)
- Проверка границ для безопасности

### Параллелизация
```go
Разделение кандидатов между воркерами:
- Каждый воркер проверяет свой чанк гвоздей
- Находим локально лучший кандидат
- Выбираем глобально лучший среди всех воркеров
```

### SSE (Server-Sent Events)
Потоковая отправка прогресса в реальном времени:
- Клиент получает каждую линию по мере генерации
- Анимация на canvas через requestAnimationFrame
- Batch flush для снижения overhead

## 📈 Сложность алгоритма

### Временная сложность
- **O(L × N × P)**
  - L = количество линий
  - N = количество гвоздей
  - P = среднее количество пикселей в линии

### Пространственная сложность
- **O(W × H + N)**
  - W × H = размер изображения
  - N = количество гвоздей

### С параллелизацией
- **O(L × (N/W) × P)**
  - W = количество воркеров
